# 발행 요청 → 피클 전달

## 흐름

```
클로드가 제작 → 콘텐츠 보드(편집) → 대표님이 [피클에 발행 요청]
   → status "발행요청"  → 이 스킬이 전달 파일 생성 → 피클이 각 채널에 등록
   → 대표님이 [발행 완료로] → 콜 기록 선택지에 뜸
```

자동으로도 돕니다: **매일 10:23 · 16:23** 정기작업이 같은 일을 합니다.
그 사이에 급하면 이 스킬로 바로 돌립니다.

## 하는 법

1. 비공개 저장소를 붙입니다 — `add_repo` 로 `spqnd13-lab/homebiz-ops` (access: push), 안내대로 한 번만 클론.
2. 아티팩트에서 콘텐츠를 내려받습니다 — `ArtifactData` `list`, 컬렉션 `content`,
   `out_dir` 로 JSON 저장 (아티팩트 주소는 `office-dashboard` 스킬 참고).
3. 전달 파일을 만듭니다.
   ```
   python3 tools/publish_handoff.py <내려받은_폴더> --out <homebiz-ops 경로>
   python3 tools/publish_handoff.py <내려받은_폴더> --dry     미리보기
   python3 tools/publish_handoff.py <내려받은_폴더> --all     이미 전달한 건도 다시
   ```
   - 상태가 `발행요청`·`발행` 이면서 `handoffAt` 이 없는 건만 넣습니다.
   - 매물번호가 있으면 매물장 확인값과 당근·네이버 문구를 같이 넣습니다.
4. **homebiz-ops 저장소에만** 커밋·푸시합니다. 메시지: `발행 요청 전달 (YYYY-MM-DD)`.
5. 전달한 건의 `handoffAt` 을 `ArtifactData` `update` 로 채웁니다(현재 `version` 을 `if_version` 에).
   대시보드에 "피클에 전달됨"으로 표시됩니다.

## 지키는 것

- 공개 저장소 `spqnd13-lab/-` 에는 콘텐츠 문구·업무 기록을 **커밋하지 않습니다.**
- 공개 문구에 호수·동 번호·연락처·비번을 넣지 않습니다(도구가 층까지만 씁니다).
- 사진·영상 파일은 제작한 쪽에 있습니다. 전달 파일에는 **무엇이 준비됐는지**를 적고,
  파일이 필요하면 대표님께 요청합니다.

## 사진·영상 파일 확인 (건너뛰지 않는다)

문구만 만들어 놓고 "준비됨"으로 넘기면 피클이 올릴 수 없다. 전달 전에 파일이 **실제로** 있는지 본다.

- 매물 콘텐츠 파일은 비공개 저장소 `assets/<매물번호>/` 에 있어야 한다.
  (예: `assets/P-295/01.jpg`, `assets/P-295/tour.mp4`)
- `publish_handoff.py` 가 자동으로 본다. 없으면 전달 파일 머리에
  **⚠️ 파일이 없어 올릴 수 없는 항목** 으로 적히고 피클은 등록하지 않는다.
- 채널별로 꼭 필요한 것: 당근·네이버 = 사진 / 인스타 피드 = 카드 이미지나 사진 /
  인스타 릴스·유튜브 = **영상**.
- **클로드는 촬영·영상 편집을 못 한다.** 사진·영상은 대표님이 올린다.
  문구·카드 이미지·릴스 대본·자막(.srt, 영상 받은 뒤)까지가 클로드 몫이다.
- 콘텐츠 보드 메모에 "사진 n장·영상 완성"처럼 적을 때는 **그 파일을 직접 확인한 뒤**에만 적는다.
  확인하지 않았으면 `assets` 칸에 `없음 — 대표님 촬영분 대기` 라고 쓴다.
