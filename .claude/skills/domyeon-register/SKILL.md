# 건물 도면 등록

도면은 `shareal/data/floorplans.js` 한 파일에 있습니다. 건물 하나를 넣으면, 그 건물의 매물 상세 창에 **[도면 보기]** 버튼이 자동으로 생기고 `floorplan.html`에서도 볼 수 있습니다.

## 원칙

- **큰 골격만.** 벽, 기둥, 출입문, 창. 가구·설비·치수는 넣지 않습니다.
- **측량하지 않습니다.** 비율이 대략 맞으면 됩니다. 화면에도 "참고용 도면"이라고 표시됩니다.
- **근거가 있는 것만.** 사용자가 준 평면도·사진·설명에 있는 것만 찍습니다. 기둥이나 문 위치를 모르면 추측하지 말고 묻거나 빼 둡니다.
- 소유자·연락처·비번은 쓰지 않습니다 (공개 파일).

## 격자 쓰는 법

한 칸이 글자 하나입니다. **모든 줄의 길이를 같게** 맞춥니다.

| 글자 | 뜻 |
| --- | --- |
| `#` | 벽 |
| `W` | 창 |
| `D` | 출입문 |
| `C` | 기둥 |
| `.` | 바닥 (실내) |
| 빈칸 | 건물 바깥 |

- 한 칸을 대략 1m로 잡으면 다루기 쉽습니다. 가로 15~30칸 정도가 휴대폰에서 보기 좋습니다.
- 바깥 테두리는 `#`·`W`·`D`로 빈틈없이 막습니다. 실내는 `.`으로 채웁니다.
- ㄱ자 건물처럼 네모가 아닌 모양은 바깥 부분을 빈칸으로 둡니다.

## 건물 하나의 모양

```js
'ait-center': {
  name: '송도 AIT센터',                    // 화면에 보일 이름
  match: ['AIT센터'],                      // 매물명·주소에 이 글자가 있으면 연결
  exclude: [],                             // 이 글자가 있으면 연결하지 않음 (선택)
  note: '기준층 사무실 구역입니다.',        // 도면 아래 한 줄 설명 (선택)
  floors: [
    {
      label: '기준층',
      grid: [
        '####WWWW####',
        '#..........#',
        'W..C....C..W',
        '#..........#',
        '####DD######'
      ],
      labels: [{ x: 5, y: 2, text: '사무공간' }, { x: 4, y: 4, text: '출입구' }]
    }
  ]
}
```

- `labels`의 `x`, `y`는 왼쪽 위를 (0, 0)으로 한 칸 위치입니다. 글자는 짧게(6자 이내) 씁니다.
- 층마다 구조가 다르면 `floors`에 여러 개를 넣습니다. 화면에 층 선택 버튼이 생깁니다.
- `match`는 겹치지 않게 정합니다. `'IT센터'`는 `'AIT센터'`에도 들어 있으므로, 이런 경우 `exclude: ['AIT']`를 씁니다.
- `sample: true`인 도면은 매물에 연결되지 않는 예시입니다. 실제 건물에는 쓰지 않습니다.

## 원본 도면이 있을 때 (권장)

호실 표시를 지운 도면 그림이 있으면, 그 그림을 바닥에 깔고 벽·기둥·문만 입체로 세웁니다. 송도 AIT센터가 이 방식입니다.

1. 도면 그림을 `shareal/images/plans/`에 넣습니다. PPT라면 호실 표시는 그림 위에 얹힌 도형이므로, PPT 안의 바탕 그림 파일(`ppt/media/`)을 그대로 쓰면 호실 표시가 빠집니다.
2. `python3 tools/domyeon/extract.py 그림.png 결과` 로 벽선·기둥·문을 읽습니다.
3. **`결과_debug.png`를 열어 원본과 맞는지 확인합니다.** 파란 선이 벽, 갈색 네모가 기둥, 주황 점이 문입니다. 엉뚱하게 읽혔으면 이 방법을 쓰지 않고 아래 "순서"대로 직접 찍습니다.
4. `python3 tools/domyeon/mkgrid.py …` 로 격자를 만들고 `floorplans.js`에 옮깁니다 (각 도구 맨 위 설명 참고).
5. 층 항목에 `image: { src, w, h, x0, y0, cell }`을 적습니다. 그림의 (x0, y0) 픽셀이 격자의 (0, 0), `cell` 픽셀이 한 칸입니다. 건물 바깥의 격자선·글자를 가리려면 `clip: true`를 넣습니다.

그림을 깔면 벽이 원본 선 위에 정확히 올라가야 합니다. 어긋나 보이면 `x0`, `y0`, `cell`이 틀린 것입니다.

## 층과 호실 연결

- `levels: [7, 8, 9]` — 이 도면이 맞는 층. 적어 두면 **그 층의 매물에만** [도면 보기]가 나옵니다. 층마다 구조가 다른 건물은 꼭 적습니다. 확인하지 못한 층은 넣지 않습니다.
- `units: [{ x, y, text: '143' }]` — 호실 번호 위치. 매물에서 도면을 열면 그 호실만 빨갛게 표시됩니다.
- `unitSuffix: true` — 여러 층이 같은 도면을 쓸 때. `units`의 `text`를 끝 두 자리(`'08'`)로 적으면 708호·1108호가 모두 같은 자리에 표시됩니다.

## 순서

1. 사용자에게서 건물 이름과 근거 자료(평면도 사진, 치수 없는 스케치, 말로 한 설명)를 받습니다.
2. 전체 가로·세로 비율을 정하고 격자를 그립니다. 테두리 → 실내 벽 → 기둥 → 문·창 순서로 찍으면 실수가 적습니다.
3. `shareal/data/floorplans.js`의 `window.FLOORPLANS`에 건물을 추가합니다.
4. 확인합니다.
   - `node --check shareal/data/floorplans.js` (문법)
   - 모든 줄 길이가 같은지
   - 가능하면 `shareal/floorplan.html?b=건물키`를 열어 눈으로 확인
5. `python3 .github/scripts/check_public_data.py shareal` 통과 후 커밋·푸시합니다.
6. 사용자에게 `https://spqnd13-lab.github.io/-/shareal/floorplan.html?b=건물키` 주소를 알려 주고, 틀린 곳(기둥·문 위치)을 말해 달라고 합니다.

## 고칠 때

"3번째 기둥을 오른쪽으로 두 칸" 같은 요청은 해당 줄의 글자 위치만 옮깁니다. 줄 길이가 바뀌지 않게 주의합니다.
