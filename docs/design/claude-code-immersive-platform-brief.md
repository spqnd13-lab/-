# 인천 홈앤비즈: Claude Code 개발 지시서

기준 브랜치: `feature/homebiz-secure-ledger` / 기존 PR #11. 이 문서는 다음 개발 작업의 명세다. 먼저 저장소 현황과 `AGENTS.md`, `.claude/skills/domyeon-register/SKILL.md`를 읽고 실제 구현과 차이가 있으면 코드에 맞춰 계획을 조정한다.

## 목표와 범위

송도·인천 주택, 상가·업무시설, 분양 정보를 한 플랫폼에서 탐색한다. 건물 → 층 → 호실 → 매물로 들어가는 입체 탐색을 핵심 경험으로 삼는다. 매물 상세에서는 사진, 위치, 가격, 면적, 주요 특성, 3D 공간 모형을 함께 볼 수 있게 한다. 모바일은 손가락 조작과 하단 정보 패널, PC는 지도·목록·3D·상세 정보를 나란히 볼 수 있도록 설계한다.

해외 서비스의 사용 방식은 참고하되 화면·문구·그래픽·모델·자산을 복제하지 않는다. 참고할 패턴: Zillow의 사진 위치와 평면 연동, Matterport의 전체 공간 조망과 층 이동, Bayut의 회전 가능한 3D 평면, Rightmove의 지도 영역 탐색, LoopNet/Crexi의 상업용 매물 정보, 분양 플랫폼의 공급 현황과 타입 비교. 외부 서비스의 실제 기능은 구현 전에 각 공식 페이지에서 다시 확인한다.

## 절대 조건

1. 기존 운영 홈페이지, 주택·상가 페이지, 매물장, 3D 도면, GitHub Pages 배포, 피클의 GitHub 직접 커밋 흐름을 보존한다. 피클용 API·웹훅을 새로 요구하지 않는다. 운영 브랜치에 병합하거나 실제 배포하지 않는다.
2. 공개 저장소 및 정적 페이지에 임대인·임차인·고객의 이름, 전화번호, 비공개 메모, 도어락 비밀번호를 넣지 않는다. 비공개 기록은 Supabase Auth/RLS가 적용된 보안 DB에만 둔다. 기존 공개 PIN·암호화 파일의 위험은 별도 보안 작업으로 추적하고 데이터 이관 전 삭제하지 않는다.
3. 사용자 계정 `spqnd13@gmail.com` 한 명을 기준으로 작업한다. 직원 화면·계정 추가는 다음 단계로 미룬다. 공개 페이지의 Supabase publishable key는 비밀키로 취급하지 않되 service_role 키는 절대 브라우저에 넣지 않는다.
4. 실측되지 않은 도면에 치수·창문·출입문·기둥·호실 위치를 임의로 확정 표시하지 않는다. 기존 `치수 미검증` 고지를 유지하고 자료의 출처와 확실성(`확인됨/참고/미확인`)을 데이터와 UI에 표시한다. 원본이 부족하면 공용 골격·배치만 보여 주고 미확인 부분은 빈 상태로 둔다.

## 저장소 시작점

- 홈페이지: `shareal/index.html`; 주택 `shareal/housing.html`; 상업 `shareal/commercial.html`.
- 3D 도면: `shareal/floorplan.html`, `shareal/3d/viewer.js`, `shareal/3d/compass.js`.
- 매물-도면 연결: `shareal/js/plan3d.js`의 건물명 낱말 매칭. 기존 URL `floorplan.html?p=P###`를 유지한다.
- `shareal/3d/viewer-data.js`는 자동 생성. 원본 모델 `shareal/3d/model-scripts/P###.js` 변경 후 `python3 tools/plan3d_round.py`와 `python3 tools/plan3d_catalog.py`를 따른다.
- 매물 공개 데이터 세 파일은 수동 편집 금지. `python3 tools/maemul.py`로만 변경하고 `python3 tools/maemul.py check` 실행.
- 보안 매물장: `shareal/secure-ledger.html`, `shareal/js/secure-ledger.js`, `docs/security/`의 현재 구현과 Supabase 마이그레이션 상태를 먼저 확인한다. 실제 로그인 성공을 가정하지 않는다.

## 화면 흐름과 시각 언어

| 화면 | 첫 화면에서 보이는 내용 | 핵심 동작 |
| --- | --- | --- |
| 홈 | 인천 홈앤비즈 브랜드, 주택/상업/분양 진입, 추천 건물, 검색 | 유형·지역 선택 후 기존 목록으로 이동 |
| 탐색 | PC 지도+매물 목록, 모바일 지도/목록 전환 | 가격·면적·용도·거래 유형 필터; 결과와 지도 선택 동기화 |
| 건물 | 건물 외관 또는 확인된 대표 이미지, 층 목록, 공급/매물 수 | 층 선택 → 확인된 호실 배치 표시 |
| 호실/도면 | 해당 층 도면, 선택 호실 강조, 공간 구조 설명 | 회전/확대/초기화/2D 전환, 사진 핫스폿은 실제 매칭 데이터가 있을 때만 |
| 매물 상세 | 가격·면적·층·사진·특징·도면 버튼·상담 | 공유 URL, 비교 목록, 문의 연결; 비공개 DB 필드 노출 금지 |
| 분양 | 프로젝트·타입·공급 정보 카드 | 확인된 자료에 한해 타입별 비교, 출처·확인 날짜 표시 |

시각 방향: 밝은 석재색 배경과 짙은 네이비 정보면, 브랜드 와인레드 강조색, 절제된 유리 질감, 건물과 공간의 깊이가 읽히는 조명. 건물 외관 → 선택 층 분리 → 호실 확대 → 내부 골격이라는 한결같은 공간 이동을 만든다. 3D는 배경 장식보다 정보 탐색 도구여야 한다. 상태 변화는 200~450ms 범위의 짧은 전환을 기본으로 하고 카메라 이동 중 사용자가 조작하면 즉시 제어권을 돌려준다. 지속적인 자동 회전과 과도한 패럴랙스는 사용하지 않는다.

모바일: 360px 폭부터 가로 스크롤 없이 읽을 수 있어야 한다. 터치 목표는 최소 44px, 두 손가락 확대·한 손가락 회전, 하단 패널은 스와이프와 버튼 모두 지원. 키보드 접근, 포커스 표시, 적절한 대체 텍스트, `prefers-reduced-motion`, WebGL 불가·저사양 기기의 정적 이미지/2D 도면 대체 경로를 넣는다. 이미지·모델은 해당 화면 진입 시 로드하고 기존 페이지 첫 진입을 무겁게 만들지 않는다.

## 연결 데이터 설계

기존 매물 ID와 `P###` 도면 ID를 바꾸지 않는다. 신규 공개 연결 파일은 기존 데이터를 참조하는 얇은 매핑으로 설계한다. 예시 필드: `listingId`, `buildingId`, `floorId`, `unitId`, `planId`, `sourceRef`, `verifiedAt`, `confidence`, `aliases`. 건물명 검색은 기존 `MATCH`로 호환을 유지하되, 명시적 매핑이 있으면 이를 우선한다. 동명이건물·동일 호실 중복·층 정보가 없는 경우에는 자동 추측으로 특정 호실을 연결하지 않는다. 자료가 없으면 `도면 준비 중`으로 표시한다. 지도 좌표·사진 핫스폿·분양 현황은 확인된 자료가 있을 때만 노출한다. 모든 JSON/JS 데이터는 공개된다는 전제로 검토한다.

## 구현 순서

1. **현황 기록**: 현재 페이지 링크, 기존 매물/도면 수, 샘플 매물 ID와 실제 도면 매칭, 모바일/PC 스크린샷을 기록한다. AIT센터의 확인된 층·호실을 첫 시범 사례로 고른다. 실증 자료가 있는 다른 건물 한 곳을 두 번째 사례로 고르되 자료가 부족하면 빈 상태를 구현한다.
2. **디자인 시스템과 탐색 시제품**: 기존 CSS를 존중해 재사용 가능한 카드, 필터, 지도/목록, 건물·층 선택, 하단 패널을 만든다. 홈페이지의 기존 동선은 보존하고 새로운 탐색 진입을 점진적으로 추가한다.
3. **AIT 세로 흐름 구현**: 실제 공개 매물 하나에서 건물 → 층 → 호실 → `floorplan.html?p=...` → 매물 상세까지 왕복. 선택 상태는 URL로 복원하고 뒤로 가기가 동작해야 한다. 실재하지 않는 층·호실은 선택 불가 처리한다.
4. **3D 품질 개선**: AIT 기준으로 벽 연결, 기둥, 출입문, 창호, 호실 윤곽과 레이블을 자료와 대조한다. 불확실한 벽체는 임의 생성하지 않는다. 선택 호실 강조, 투명도/층 분리, 초기화, 2D 대체 화면을 구현한다. 기존 모델 전체에 일괄 기하 변형을 적용하지 않는다.
5. **분양·비교 확장**: 자료가 검증된 프로젝트만 공급 카드로 제공한다. 비교 목록은 공개 가격/면적/위치만 저장하고 고객 정보와 섞지 않는다. 검색·필터와 신규 매물 추가 후 자동 반영을 검증한다.
6. **보안·회귀 점검**: 공개 파일의 개인정보 검사, Supabase 권한 경계, PC/모바일 브라우저 동작, 기존 피클 등록 흐름, 홈페이지 링크를 확인한다. PR에 변경 전후 화면과 미확인 자료 목록을 남긴다.

개발할 때는 보안 PR #11에 대규모 UI 변경을 섞기보다 `feature/homebiz-secure-ledger` 최신 커밋에서 `feature/homebiz-immersive-3d`를 만들어 별도 초안 PR을 연다. 첫 PR은 AIT 세로 흐름과 디자인 시제품에 한정한다. 사용자 승인 전 운영 브랜치 병합·배포 금지.

## 완료 기준

- 샘플 공개 매물에서 건물/층/호실/3D/상세를 오가며 URL 재접속과 뒤로 가기가 정상 동작한다.
- 데이터가 없는 매물과 미확인 모델은 오연결 없이 명확한 대체 상태를 보여 준다.
- 360px 모바일, 태블릿, PC에서 터치/마우스/키보드 조작과 축소 모션 설정을 확인한다. WebGL 비활성 시 정보 탐색이 계속 가능하다.
- `python3 tools/maemul.py check`, `.github/scripts/check_public_data.py`, 도면 카탈로그 생성 검증, 기존 페이지 링크 검사 통과. 자동 등록 매물이 공개 목록에 남고 홈페이지·매물장·3D 버튼이 정상 연결된다.
- 익명 방문자는 Supabase 비공개 기록을 읽거나 수정하지 못한다. 공개 응답·콘솔·정적 파일에 PII가 없다. 보안 계정의 실제 로그인·RLS 테스트는 운영 사용자 인증 가능 시 검증하고 미검증 결과를 성공으로 쓰지 않는다.
- 변경 파일, 화면 캡처, 재현 가능한 테스트 절차, 알려진 한계, 배포 전 승인 필요 사항을 PR에 적는다.
