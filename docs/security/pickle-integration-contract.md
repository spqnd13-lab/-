# 피클 GitHub 직접 등록 연동 — 확인된 현행 구조 및 보안 전환 계약

## 확인된 사실 (사용자가 제공한 피클 운영 설명)
- 피클은 별도 웹훅/API 없이 연결된 GitHub 계정 `spqnd13-lab`으로 공개 저장소 `spqnd13-lab/-`에 직접 커밋·푸시한다.
- 매물 공개 정보는 `tools/maemul.py`와 `AGENTS.md` 규칙을 통해 `shareal/data/properties.json`, `shareal/properties_data.js` 등에 반영한다.
- `contacts` 필드는 빈 값으로 유지하며, `STORAGE_KEY` 버전 갱신 후 `main` 푸시 → GitHub Actions → GitHub Pages 자동 배포.
- 비공개 정보는 기기별 `localStorage` 및 `shareal/secure/private.enc.json` 기반이다. 피클이 대표자의 브라우저 저장소나 암호화 파일을 원격으로 갱신하는 경로는 없다.
- 피클은 암호화 비밀번호를 저장하거나 입력하지 않는다. 기존 암호화 파일의 업데이트는 사용자가 브라우저에서 수행한다.

## 반드시 유지할 것
1. 공개 매물 등록은 기존 피클 → GitHub → GitHub Pages 흐름을 유지한다.
2. `AGENTS.md`, `tools/maemul.py`, `.github/scripts/check_public_data.py`의 공개 데이터 보호 검사를 우회하지 않는다.
3. 매물번호 `legacy_listing_id`를 보안 DB의 연결 키로 사용한다. GitHub에 개인정보를 쓰지 않는다.
4. 운영 매물, 로컬 브라우저 정보, 암호화 파일을 자동 삭제하거나 이전하지 않는다.
5. 피클의 GitHub 토큰에 비공개 DB 권한을 부여하지 않는다.

## 단계별 구현
### 1단계: 보안 매물장
- Supabase Auth 또는 동등한 서버 인증을 별도 구성한다. 직원별 관리자/담당자 권한을 서버 DB에서 검증한다.
- 기존 공개 매물은 매물번호를 통해 읽기 전용 동기화한다. 공개 JSON에 없더라도 비공개 연락처를 임의 삭제하지 않는다.
- 직원은 로그인 후 임대인·임차인 이름/전화번호와 비공개 메모를 DB에 입력·수정할 수 있다.
- 일반 고객에게는 연락처가 포함된 API, 테이블, 로그, 캐시를 제공하지 않는다.
- 기존 정적 PIN은 서버 인증을 대체하지 않으며, 안전한 전환 시점에 폐기한다.

### 2단계: 피클 비공개 정보 자동 입력 (별도 승인 후)
- 피클의 실행 환경에서 안전하게 보관 가능한 인증 수단과 권한 범위를 확인한다.
- 서버 측 좁은 범위의 등록 API를 구현한다. GitHub 저장소나 브라우저에 서버 비밀키를 두지 않는다.
- 중복 방지 키, 감사 기록, 입력 검증, 연락처 마스킹, 오류 재시도, 데이터 주체 동의 및 보존 정책을 갖춘다.
- 실데이터 없이 가짜 번호로 종단간 테스트 후 전환한다.
- 비공개 API 연결이 불가능하다면 공개 매물 자동 접수 + 직원 로그인 후 비공개 연락처 수동 입력으로 운영한다.

## 미해결 사항
- 보안 DB 및 인증 서비스 선택과 소유 계정 설정
- 피클 실행 환경에서 외부 API를 안전하게 호출할 수 있는지 여부
- 기존 암호화 보안자료의 복원·이전 방법과 공개 저장소 내 암호화 파일의 노출 위험 대응
- 임대인/임차인 연락처의 수집 목적, 접근 권한, 보존·삭제 정책

## 보안 검증
- 미인증 요청, 타 직원의 비공개 매물 요청, 공개 페이지 직접 API 호출은 모두 거부
- 피클의 공개 GitHub 커밋에 연락처가 절대 포함되지 않음
- 매물번호 중복·수정·재등록·삭제에도 비공개 연락처 무단 덮어쓰기 없음
- 운영 배포와 마이그레이션은 사용자 승인 후 진행
