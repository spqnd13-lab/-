# 피클 자동 연동 호환성 계약 — 조사 전 단계

**주의:** 현재 저장소에서 피클 자동 연동 구현을 특정하지 못함. 아래는 새 연동 구현이 아니라 기존 연동을 보존하기 위한 점검 명세다.

## 실제 연동 조사
- 접수 이벤트 시작 지점, 실행 환경(피클 앱/Claude Code/서버/브라우저), 수신 주소, 호출 주체를 확인.
- 기존 매물 번호 발급 규칙과 `tools/maemul.py` 실행 경로를 확인.
- 피클이 전달하는 필드와 개인정보 동의/수집 경로 확인. 실제 연락처 값은 보고서에 출력하지 않음.
- 접수 성공/실패/재시도/중복/수정/삭제 동작을 가짜 데이터로 확인.
- 인증 정보는 환경변수 또는 비밀 저장소에만 두고 GitHub 저장소에 기록하지 않음.

## 정규화된 내부 데이터 예시 (가짜 값)
```json
{
  "source": "pickle",
  "sourceEventId": "example-event-001",
  "listing": {
    "externalId": "example-listing-001",
    "title": "테스트 상가",
    "tradeType": "월세",
    "deposit": 2000,
    "monthlyRent": 150
  },
  "privateContacts": {
    "landlord": {"name": "테스트임대인", "phone": "TEST_PHONE"},
    "tenant": {"name": "테스트임차인", "phone": "TEST_PHONE"}
  }
}
```
위 필드는 **내부 목표 구조 예시**이며 피클의 실제 API 필드가 아님.

## 수신 요구사항
- 인증 실패 401/403; 잘못된 입력 400; 동일 `sourceEventId` 재처리 시 무해한 응답.
- 공개 매물 테이블과 비공개 연락처 테이블 분리 저장.
- 연락처 변경은 권한 검증 후 이력 기록.
- 네트워크 실패 시 재시도 및 수동 재처리, 중복 방지.
- 기존 자동 접수 검증 전에는 새 endpoint로 전환하지 않음.
